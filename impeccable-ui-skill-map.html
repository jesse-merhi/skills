Impeccable replaces Anthropic frontend-design.

Use Impeccable for design direction, keep browser proof.

The new split is simple: Impeccable shapes, critiques, and polishes the UI; frontend-ui-validation proves the rendered page works with screenshots, layout audits, console checks, and impeccable detect.

Skill changes this implies

Remove

Delete Anthropic frontend-design from external installs and installed harness folders.

  • No $frontend-design routing.
  • No skills add anthropics/skills install path.

Route

Use $impeccable for design-adjacent work, including planning and code review UI lenses.

  • AGENTS.md routes frontend UI design to Impeccable.
  • code-review can add Impeccable as a focused UI subagent.

Prove

Keep frontend-ui-validation as the rendered proof gate, with Impeccable detection inside it.

  • Layout audit for measurable DOM failure.
  • Detector output for design anti-patterns.

Validation command now expected

The detector is part of the UI validation queue. A clean screenshot is no longer enough when Impeccable flags a real anti-pattern.

Required alongside screenshots and layout audit
npx --yes impeccable@3.0.3 detect <changed-ui-path-or-url> --json

Prefer a running URL. Use changed UI files when browser scanning is blocked.

Creative use beyond basic UI tasks

Use $impeccable critique as an early design-review lens in planning. Use $impeccable harden before code-review when the diff has long names, empty states, i18n, or error flows. Use $impeccable document before a large UI refactor so future agents inherit the visual system instead of re-guessing it.

For PR review, pair it with frontend-ui-validation: Impeccable names design issues; the validation skill proves the rendered browser behavior.
