# Frontend spec guidance

For frontend UI work, capture the design direction and rendered validation bar before publishing:

- name the audience, product or brand register, tone, structure, existing tokens, anti-references, interaction intent, and likely visual risk
- include acceptance criteria for the important states and viewports
- name the implementation owner and rendered proof expected during review: web viewport or native device, screenshots, interactions, layout checks, or traces
- let tickets, review, and proof-pack work reuse that evidence while it remains current
