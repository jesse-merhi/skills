# Assess affected UI

Review visuals and interactions in the same rounds as the code. Before round one, derive criteria from the user's goal, affected journey and design system. Consider task clarity, hierarchy, spacing, typography, accessibility, responsiveness, and loading, empty and error states. Record baseline and any reference screenshots with their provenance. Report missing captures without inventing replacements. Keep criteria, states and viewports fixed across rounds unless the user changes them.

Use the implementation owner's captures and interaction evidence for each reviewer. Report missing captures or interaction proof as a limit. Visual improvement requires rendered evidence.

Tie each finding to a screenshot region or interaction, the unmet criterion, its impact on the user and a small proposed fix. Distinguish observed defects from design judgment. Each applied improvement triggers another round. Apply supported, in-scope improvements with clear user impact. Keep taste-level refinements minor in ordinary review. Preserve product direction and functionality, and keep redesign, feature work and separate visual review outside this workflow. Compare before and after captures against the same criteria and check for regressions.
